## สิ่งที่เราพูดคุยกัน (สรุปใจความสำคัญ)

### 1. แยก "Parallelism" ออกจาก "Algorithmic Improvement"
- Multi-thread, SIMD, GPU = Parallelism (เพิ่ม throughput โดยเพิ่ม hardware)
- Better complexity, fewer ops/byte, cache-friendly = Algorithmic Improvement (ดีขึ้นที่รากฐาน)
- การเปรียบเทียบที่ fair: **Single-thread cycles/byte** หรือ **Work per byte**

### 2. Current XMLFastReader อยู่ที่ไหนแล้ว
- TOC Table (DFA simulation) = O(1) per byte → **Optimal complexity แล้ว**
- Bit-flags (7 bits) = Minimal state representation
- Trie lookup = Optimal prefix matching สำหรับ registered paths
- Zero-copy = Information-theoretic lower bound สำหรับ data movement
- **สรุป**: อยู่ระดับ "Very Good" สำหรับ single-threaded Java แล้ว

## อัลกอริทึมที่ "เร็วกว่าทางทฤษฎี" (Single-Thread)

### 1. SIMD Vectorized Parsing (Parabix Style) ⭐⭐⭐
**หลักการ**: ประมวลผล 16-64 bytes ต่อ instruction ด้วย vector registers
```
Scalar:     byte-by-byte state transition (1 byte/cycle)
Vector:     32-64 bytes/cycle ด้วย AVX2/AVX-512/NEON
```
**Key Techniques**:
- **Parallel Bit Streams**: แปลง input เป็น bit streams (is_lt, is_gt, is_quote, is_slash...)
- **Bitwise State Machine**: ใช้ AND/OR/XOR/SHIFT บน vector registers ทำ state transition หลายตัวพร้อมกัน
- **Shuffle-based Tokenization**: vpshufb หา delimiters ทีละ 32 bytes
- **Branchless**: ใช้ blend/mask แทน branch → กำจัด branch misprediction

**ทฤษฎี**: O(n/w) โดย w = vector width (32-64) vs O(n) scalar
**Speedup ทางอัลกอริทึม**: 3-5x cycles/byte

**References**: 
- Parabix XML Parser (Cameron et al.)
- simdjson (Lemire et al.) - แม้จะเป็น JSON แต่วิธีเดียวกัน
- "Bit-Parallel XML Parsing" papers

---

### 2. Perfect Hash + Rolling Hash for Tag Matching ⭐⭐
**หลักการ**: แทน trie linear scan (O(k) byte compares) ใช้ hash O(1) worst-case
```
Current:  for each child: compare nameLen bytes → O(k * avg_len)
Perfect:  hash(tag) → direct index → O(1) guaranteed
Rolling:  hash update per byte = O(1) → early rejection
```
**Algorithms**:
- **CHM / BDZ / PTHash** - Minimal Perfect Hash Function (MPHF)
- **Rabin-Karp Rolling Hash** - hash = (hash * BASE + byte) % MOD
- **Compile-time generation**: registered paths คงที่ → generate hash function ครั้งเดียว

**Speedup**: 2-3x สำหรับ tag-heavy XML (หลาย registered paths)

---

### 3. Branchless State Machine ⭐⭐
**หลักการ**: แปลง TOC table ให้ไม่มี branch
```
Current:  TOC[flags][byte].call(runner) → virtual call / branch
Branchless: ใช้ lookup table + arithmetic/bitwise ops
```
**Techniques**:
- **State transition table**: next_state[state][byte] = new_state (uint8)
- **Action table**: action[state][byte] = encoded action (bitmask)
- **Decode action**: bitwise ops แทน function call
- **Predicated execution**: cmov / blend / mask

**Speedup**: 1.5-2x cycles/byte (กำจัด branch mispredict ~15-20 cycles/miss)

---

### 4. DFA Minimization (Hopcroft's Algorithm) ⭐
**หลักการ**: ลดจำนวน states ใน TOC ให้น้อยที่สุด
```
Current:  128 flag combinations × 256 bytes = 32,768 cells
Minimized: equivalent states รวมกัน → อาจเหลือ 20-40 states
```
**ประโยชน์**:
- TOC table เล็กลง → L1 cache fit ดีกว่า
- Fewer cache misses
- Branch predictor เรียนรู้ pattern ง่ายขึ้น

**Speedup**: 1.2-1.5x (ขึ้นอยู่กับ cache behavior)

---

### 5. Succinct Data Structures / Rank-Select ⭐⭐⭐ (Advanced)
**หลักการ**: แทน parse แล้วสร้าง tree ให้ encode โครงสร้างไว้ใน bit vector
```
Bit vector B[1..n]: B[i]=1 ถ้า byte i เป็น '<' เริ่ม tag
Rank(i) = จำนวน 1s ใน B[1..i] → tag ที่ i คือ tag ลำดับที่ Rank(i)
Select(k) = ตำแหน่งของ 1 ลำดับที่ k → tag ลำดับที่ k อยู่ที่ byte Select(k)
```
**Balanced Parentheses (BP)**: แสดง tree structure ใน 2n bits
- navigate parent/child/sibling ใน O(1) ด้วย rank/select
- **ไม่ต้อง parse ทุกครั้ง** — query ตรงบน compressed representation

**Use case**: Random access, XPath, query-heavy workloads
**Space**: n + o(n) bits (near information-theoretic minimum)

---

### 6. Compressed Parsing (Parse on Compressed Data) ⭐⭐
**หลักการ**: Parse ตรงบน compressed representation
- **LZ77 factors**: parse บน factors แทน raw bytes
- **Grammar-based** (RePair, Sequitur): parse บน grammar rules
- **Speedup**: O(z) โดย z = compressed size << n

## Mindset สำคัญ (Internalize These)

1. **Measure First**: ไม่มี optimization ใดคุ้มค่าโดยไม่มี baseline measurement
   - ใช้ JMH, perf, async-profiler, Intel VTune
   - วัด: cycles/byte, cache miss rate, branch miss rate, IPC

2. **Complexity ≠ Performance**: O(n) ทั้งคู่ แต่ constant factor ต่างกัน 10x ได้
   - Memory access pattern สำคัญกว่า operation count
   - Branch prediction สำคัญกว่า instruction count

3. **Hardware Awareness**: เขียนโค้ดให้ hardware ทำงานได้เต็มที่
   - Sequential access → prefetcher happy
   - Small working set → cache happy
   - Predictable branches → branch predictor happy
   - Vectorizable loops → SIMD happy

4. **Trade-offs ทุกอย่าง**: ไม่มี free lunch
   - Speed vs Memory vs Complexity vs Maintainability
   - เลือกตาม use case จริง ไม่ใช่ benchmark แบบ synthetic

5. **Algorithmic Thinking > Library Knowledge**:
   - เข้าใจ "ทำไม" จึงจะปรับ "อย่างไร" ได้
   - Library เปลี่ยนได้ หลักการอยู่ตลอดกาล
