# XML2TXT Function Descriptions

## Overview
This document describes all functions required for the XML2TXT application, including their algorithms, inputs, outputs, and test cases. Functions are organized by category and will be implemented in LabRat.java first, then copied to XML2TXT.java.

## Function Categories

### 1. File System Functions

#### 1.1 ListAllFile(folder)
**Purpose:** Recursively list all .xml and .zip files in a directory and its subdirectories.

**Algorithm:**
1. Create a list to store file paths
2. Use File object to check if folder exists and is a directory
3. List all files and directories in the folder
4. For each item:
   - If it's a file and has .xml or .zip extension, add to list
   - If it's a directory, recursively call ListAllFile on it
5. Return comma-separated string of file paths

**Input:**
- `folder`: String path to the directory to search

**Output:**
- String: Comma-separated list of .xml and .zip file paths
- Example: "path/file1.xml,path/subdir/file2.zip,path/file3.xml"

**Test Cases:**
1. Empty directory: Returns empty string ""
2. Directory with only .xml files: Returns all .xml files
3. Directory with only .zip files: Returns all .zip files
4. Nested directories: Returns files from all levels
5. Directory with mixed file types: Returns only .xml and .zip files
6. Non-existent directory: Should handle gracefully (return empty or throw exception)
7. File with spaces in path: Should handle correctly
8. Hidden files: Should be included if they match extension

#### 1.2 ParseArguments(args)
**Purpose:** Parse command-line arguments (-p, -s, -d, -t) into configuration variables.

**Algorithm:**
1. Initialize default values:
   - pathBP = null
   - sourcePath = "."
   - destPath = "."
   - threadCount = 1
2. Iterate through args array:
   - For "-p": Set pathBP to next argument
   - For "-s": Set sourcePath to next argument
   - For "-d": Set destPath to next argument
   - For "-t": Parse next argument as integer for threadCount
   - For unknown arguments: Print error and exit
3. Return configuration object or set instance variables

**Input:**
- `args`: String array of command-line arguments

**Output:**
- Configuration object or set of instance variables:
  - pathBP: String path to .bp configuration file
  - sourcePath: String source directory path
  - destPath: String destination directory path
  - threadCount: int number of worker threads

**Test Cases:**
1. No arguments: Uses all defaults
2. Single argument: Error handling
3. All arguments present: Correct parsing
4. Invalid thread count: Error handling
5. Missing required argument: Error handling
6. Argument order variations: Should work regardless of order
7. Path with spaces: Should handle correctly
8. Negative thread count: Should handle gracefully

### 2. Configuration File Functions

#### 2.1 ReadBPFile(pathBP)
**Purpose:** Read and parse .bp configuration file to extract file and path information.

**Algorithm:**
1. Read file content line by line
2. Parse each line:
   - Skip empty lines and comments
   - For "file:filename" lines: Store file name
   - For "entity:path" lines: Store entity path
   - For "-path@attr" or "-path#text" lines: Store column specification
3. Handle shorthand notation (././tag)
4. Build data structures:
   - List of files to process
   - List of entity paths
   - HashMap of column specifications per file
5. Return parsed configuration

**Input:**
- `pathBP`: String path to .bp configuration file

**Output:**
- Configuration object containing:
  - files: List<String> of file names
  - entities: List<String> of entity paths
  - columns: Map<String, List<ColumnSpec>> mapping file names to column specifications

**ColumnSpec Structure:**
```java
class ColumnSpec {
    String path;        // Full path (e.g., "/Transaction/Invoid@SN")
    String type;        // "@" for attribute, "#" for inner text
    String attrName;    // Attribute name (if type is "@")
    int columnIndex;    // Column position in output
}
```

**Test Cases:**
1. Empty .bp file: Returns empty configuration
2. Valid .bp file with example 1: Correct parsing
3. Valid .bp file with example 2: Correct parsing
4. Malformed line: Error handling
5. Duplicate entries: Should handle (overwrite or error)
6. Path with spaces: Should handle correctly
7. Mixed entity and column lines: Correct separation
8. Shorthand notation (././tag): Correct expansion

#### 2.2 RegisterPathsWithXmlBluePrint(config)
**Purpose:** Register parsed paths with xmlBluePrint for data extraction.

**Algorithm:**
1. For each file in config.files:
   - Create unique idToken for the file
   - For each entity in config.entities:
     - Register entity path with entity handler
   - For each column in config.columns[file]:
     - Register column path with column handler
2. Set thread count using xmlBluePrint.setThreadCount()
3. Return registration status

**Input:**
- `config`: Configuration object from ReadBPFile()

**Output:**
- Registration status: boolean (true if successful)

**Entity Handler:**
```java
public boolean call(Object idToken, xmlBluePrintHolder holder, int event,
                   int nameStart, int nameEnd, int valueStart, int valueEnd) {
    if (event == EV_OPEN_TAG) {
        // Reset output buffer for new entity
        return;
    }
    if (event == EV_CLOSE_TAG) {
        // Write entity data to output file
        return;
    }
    return true;
}
```

**Column Handler:**
```java
public boolean call(Object idToken, xmlBluePrintHolder holder, int event,
                   int nameStart, int nameEnd, int valueStart, int valueEnd) {
    if (event == EV_ATTR) {
        // Extract attribute value and store in buffer
        return;
    }
    if (event == EV_INNER_TEXT) {
        // Extract inner text and store in buffer
        return;
    }
    return true;
}
```

**Test Cases:**
1. Valid configuration: All paths registered successfully
2. Invalid path: Error handling
3. Duplicate registration: Should handle (overwrite or error)
4. Empty configuration: No registrations
5. Complex paths: Correct registration
6. Thread count setting: Correct configuration
7. Entity and column registration: Both work
8. Handler implementation: Correct callback behavior

### 3. File Processing Functions

#### 3.1 ProcessFiles(sourcePath, destPath, threadCount, config)
**Purpose:** Main file processing function that coordinates the entire conversion process.

**Algorithm:**
1. List all .xml and .zip files using ListAllFile()
2. Create output directory if it doesn't exist
3. Initialize xmlBluePrint with threadCount
4. Register paths using RegisterPathsWithXmlBluePrint()
5. Submit files to xmlBluePrint job queue:
   - For each file:
     - Check if job queue has space
     - If space available: Submit file
     - If no space: Wait and retry
6. Run xmlBluePrint processing
7. Wait for completion (xmlBluePrint.isReadyToDown())
8. Shutdown xmlBluePrint
9. Generate metadata files (read_*, success_*, fail_*)
10. Rename processed files (xmlFileName.bak, zipXMLZipFile.bak)

**Input:**
- `sourcePath`: String source directory path
- `destPath`: String destination directory path
- `threadCount`: int number of worker threads
- `config`: Configuration object

**Output:**
- Processing status: boolean (true if successful)
- Generated files: List<String> of output files created

**Test Cases:**
1. No input files: Should handle gracefully
2. Single .xml file: Complete processing
3. Single .zip file: Complete processing
4. Multiple files: All processed
5. Invalid source path: Error handling
6. Invalid destination path: Error handling
7. Thread count variations: Should work with different values
8. Complex .bp configuration: Correct processing
9. File renaming: Correct renaming after processing
10. Metadata generation: All metadata files created

#### 3.2 WriteOutputFile(threadNo, fileId, data)
**Purpose:** Write extracted data to output file.

**Algorithm:**
1. Check if output file exists for threadNo and fileId
2. If file doesn't exist: Create new file with header
3. Append data to file
4. If buffer size exceeds threshold: Flush to disk
5. Return write status

**Input:**
- `threadNo`: int thread identifier (0 to threadCount-1)
- `fileId`: String file identifier
- `data`: String data to write

**Output:**
- Write status: boolean (true if successful)

**Test Cases:**
1. First write to file: Creates file with header
2. Subsequent writes: Appends to existing file
3. Large data: Handles correctly
4. Invalid threadNo: Error handling
5. Invalid fileId: Error handling
6. Concurrent writes: Thread-safe
7. File permissions: Error handling
8. Disk space: Error handling

### 4. Utility Functions

#### 4.1 GenerateOutputFilename(threadNo, fileType, timestamp)
**Purpose:** Generate standardized output filename.

**Algorithm:**
1. Format threadNo as "0" + threadNo (e.g., "00", "01")
2. Get current timestamp in format "yyyyMMddHHmmss"
3. Combine: fileType + "_" + threadNo + "_" + timestamp + ".txt"
4. Return filename

**Input:**
- `threadNo`: int thread identifier
- `fileType`: String file type (e.g., "Invoids", "Items", "read", "success", "fail")
- `timestamp`: String timestamp (optional, generates if not provided)

**Output:**
- String: Formatted filename

**Test Cases:**
1. Different thread numbers: Correct formatting
2. Different file types: Correct naming
3. Different timestamps: Correct formatting
4. Edge cases: threadNo = 0, 9, 99

#### 4.2 GeneratePendingFilename(fileType, threadNo)
**Purpose:** Generate pending filename for files being written.

**Algorithm:**
1. Format threadNo as "0" + threadNo
2. Combine: fileType + "_" + threadNo + "_pending"
3. Return filename

**Input:**
- `fileType`: String file type
- `threadNo`: int thread identifier

**Output:**
- String: Pending filename

**Test Cases:**
1. Different thread numbers: Correct formatting
2. Different file types: Correct naming
3. Edge cases: threadNo = 0

#### 4.3 RenameProcessedFile(originalPath)
**Purpose:** Rename processed file to prevent duplicate processing.

**Algorithm:**
1. Check file extension:
   - If ".xml": Rename to "xml" + originalName + ".bak"
   - If ".zip": Rename to "zip" + originalName + ".bak"
2. Perform rename operation
3. Return rename status

**Input:**
- `originalPath`: String original file path

**Output:**
- Rename status: boolean (true if successful)

**Test Cases:**
1. .xml file: Correct renaming
2. .zip file: Correct renaming
3. Non-.xml/.zip file: Should not rename
4. File permissions: Error handling
5. File already exists: Error handling
6. Path with spaces: Should handle correctly
