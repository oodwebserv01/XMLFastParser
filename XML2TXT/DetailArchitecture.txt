# XML2TXT Application Architecture

## Overview
XML2TXT is a Java command-line application that converts XML files to text format using the xmlFastParser library. It processes XML files based on configuration files (.bp format) and generates output text files with structured data extraction.

## Main Components

### 1. XML2TXT Class (Main Entry Point)
**Location:** `xml2txt.XML2TXT`
**Type:** Command-line application (single .java file)

**Responsibilities:**
- Parse command-line arguments (-p, -s, -d, -t)
- List all .xml and .zip files recursively from source directory
- Read and parse .bp configuration file
- Register XML paths with xmlBluePrint
- Process files using xmlBluePrint with specified thread count
- Generate output files in destination directory

**Key Methods:**
- `main(String[] args)` - Entry point and argument parsing
- `ListAllFile(String folder)` - Recursive file listing

### 2. xmlBluePrint (from xmlFastParser package)
**Location:** `xmlFastParser.xmlBluePrint`
**Type:** XML parsing and processing engine

**Architecture:**
- **State Machine (24 states):** Handles all XML parsing states (OUTSIDE_ROOT, ROOT_LT, ROOT_PI, etc.)
- **TOC Table (24x256):** Transition table mapping state/byte to handlers
- **Handler System:** Processes XML events (openTag, closeTag, attribute, innerText)
- **Path Registration:** Registers extraction paths using hash-based matching
- **Thread Management:** Supports multi-threaded processing with holder.getThreadNO()

**Key Features:**
- Hash-based path matching using FNV-1a with SplitMix64 finalizer
- Unregistered branch handling with tag-name based unwind (no depth limit)
- Real-time data extraction via callbacks
- Memory-efficient circular buffer job queue

### 3. xmlBluePrintHolder (from xmlFastParser package)
**Location:** `xmlFastParser.xmlBluePrintHolder`
**Type:** Non-XML logic and thread coordination

**Responsibilities:**
- Job queue management (circular buffer)
- Thread pool coordination
- Memory/buffer management
- Current job pointer/state tracking
- Charset storage and target/child hash sets
- Thread number assignment (holder.getThreadNO())

### 4. xmlBluePrintCall Interface (from xmlFastParser package)
**Location:** `xmlFastParser.xmlBluePrintCall`
**Type:** Callback interface for data extraction

**Method Signature:**
```java
public void call(Object idToken, xmlBluePrintHolder holder, int event,
                 int nameStart, int nameEnd, int valueStart, int valueEnd);
```

**Parameters:**
- `idToken`: Identifies which path this event belongs to
- `holder`: Contains data for the job being processed
- `event`: Event type (0=error, 1=openTag, 2=closeTag, 3=attribute, 4=innerText)
- `nameStart/End`: Byte range for tag/attribute names
- `valueStart/End`: Byte range for attribute values or inner text

## Data Flow

### 1. Configuration Processing
1. Parse .bp file to extract:
   - File names (file:filename)
   - Entity paths (entity:path)
   - Column specifications (-path@attr or -path#text)

2. Register paths with xmlBluePrint:
   - Convert relative paths to absolute
   - Handle shorthand notation (././tag)
   - Create hash-based lookup tables

### 2. File Processing
1. **File Discovery:** Use ListAllFile() to find .xml and .zip files
2. **Job Queue:** Submit files to xmlBluePrint job queue
3. **Multi-threaded Processing:**
   - xmlBluePrint.run() processes queued jobs
   - Worker threads extract data via callbacks
   - holder.getThreadNO() identifies processing thread

### 3. Data Extraction
1. **Entity Processing:** Each entity becomes a row in output
2. **Column Processing:** Each column specification becomes a field
3. **Output Generation:**
   - Thread-local buffers collect extracted data
   - Files written when entities complete
   - Output format: ????????_[ThreadNO]_[YYYYMMDDHHmmss].txt

## Thread Architecture

### Worker Threads
- Each thread processes XML jobs independently
- holder.getThreadNO() provides thread identification (0 to threadCount-1)
- Thread-local storage for output buffers
- Per-thread CSV file writers (for XML2CSV variant)

### Thread Coordination
- xmlBluePrint.setThreadCount(n) configures thread pool
- Circular buffer manages job queue with backpressure
- xmlBluePrint.isReadyToDown() signals completion
- Graceful shutdown after queue empty

## File Naming and Management

### Input Files
- .xml files: Processed directly
- .zip files: Contents extracted and processed

### Output Files
- Primary output: ????????_[ThreadNO]_[YYYYMMDDHHmmss].txt
- Pending files: ????????_[ThreadNO]_pending (during writing)
- Metadata files:
  - read_YYYYMMDDHHmmss.txt (files read)
  - success_YYYYMMDDHHmmss.txt (successful conversions)
  - fail_YYYYMMDDHHmmss.txt (failed conversions)

### File Renaming
- After successful conversion: xmlFileName.bak (for .xml)
- After successful conversion: zipXMLZipFile.bak (for .zip)
- Prevents duplicate processing

## Error Handling

### XML Parsing Errors
- Malformed XML in registered branches: Triggers error callbacks
- Malformed XML in unregistered branches: Silently ignored (skip mode)

### File Processing Errors
- File not found: Added to fail_*.txt
- Permission errors: Added to fail_*.txt
- Conversion failures: Added to fail_*.txt

### Recovery
- Continue processing other files
- Maintain processing state
- Generate failure reports

## Performance Considerations

### Memory Management
- Circular buffer for job queue (bounded memory)
- Hash-based path lookup (O(1) access)
- Thread-local buffers (reduce contention)

### Processing Efficiency
- FNV-1a hash with SplitMix64 finalizer (fast hashing)
- Early termination on namespace characters (:, })
- No depth limit for unregistered branches
- Batch processing with pending files

### Scalability
- Multi-threaded processing
- Configurable thread count
- Bounded memory usage
- Streaming file processing

## Deployment

### Command Line Usage
```bash
java XML2TXT [-p path/file.bp] [-s sourcePath] [-d destPath] [-t threadCount]
```

### Configuration
- .bp file: Defines extraction paths and columns
- Source directory: Where input files are located
- Destination directory: Where output files are written
- Thread count: Number of worker threads (default: 1)

### Dependencies
- xmlFastParser.jar (required)
- Java 17+ (required)
- UTF-8 encoding (required)
