1. Overview

XMLFastReader is a high-performance, multi-threaded XML parser for Java that uses a table-driven Finite State Machine (FSM) to achieve zero-allocation parsing on the hot path. It's designed for processing large volumes of structurally similar XML files with minimal overhead.

Key Features

  • Byte-level FSM — O(1) per-byte dispatch via transition table (TOC)
  • Zero-copy callbacks — Events return offsets into original byte buffer
  • Path-based targeting — Register only the XML paths you care about
  • Multi-threaded — Lock-free ring buffers, configurable worker threads
  • Predictive shortcuts — Learns structural fingerprints to skip non-target regions
  • UTF-8 fast path — Multi-byte sequences skipped in bulk
Requirement: Java 9+ (uses VarHandle.fullFence() for memory barriers)

2. Quick Start

import xmlFastParser.*;

public class MyParser {
    public static void main(String[] args) {
        // 1. Create blueprint
        xmlBluePrint bp = new xmlBluePrint();

        // 2. Register paths you want to extract
        bp.regist("/catalog/book", new MyHandler(), "book");
        bp.regist("/catalog/book/author", new MyHandler(), "author");
        bp.rootRegist(new MyHandler(), "root");
        bp.errorRegist(new MyHandler(), "error");

        // 3. Configure threads (optional, defaults to 1)
        bp.setThreadCount(4);

        // 4. Start engine
        bp.run();

        // 5. Submit XML jobs
        byte[] xml = readFile("data.xml");
        bp.pushJob(xml, xml.length, "data.xml".getBytes(), "data.xml".length());

        // 6. Wait and shutdown
        bp.shutdown(false);
    }
}

3. Path Registration

xmlBluePrint.regist(path, handler, token)

Registers an XPath-like path for event callbacks. Only the last segment receives callbacks.

ParameterDescription
pathAbsolute path starting with / (e.g., /root/item/name)
handlerxmlBluePrintCall implementation
tokenUser object passed back in callbacks (identifies which path triggered)

Examples

// Target: /catalog/book - fires on  open/close
bp.regist("/catalog/book", handler, "book");

// Target: /catalog/book/author - fires on  inside book
bp.regist("/catalog/book/author", handler, "author");

// Intermediate nodes (/catalog, /catalog/book) are routing only - no callbacks

Root Registration

bp.rootRegist(rootHandler, rootToken);

Called when root element opens/closes. Use for document-level initialization.

Error Registration

bp.errorRegist(errorHandler, errorToken);

Called for malformed XML, tag mismatches, EOF errors.

Namespace handling: Tag names are hashed stopping at : or }, so ns:Book and Book match the same registration.

7. Lifecycle Control

Start

bp.run();  // Starts distributor + worker threads

Pause/Resume

bp.pause();   // Workers finish current job, then park
bp.resume();  // Resume processing

Shutdown

bp.shutdown(false);  // Graceful: drain queues, join threads
bp.shutdown(true);   // Force: abandon pending jobs immediately
Always call shutdown() to avoid thread leaks.

8. Predictive Shortcuts (Advanced)

XMLFastReader automatically learns structural fingerprints from processed XML files and uses them to accelerate parsing of similar files.

How It Works

  1. Each parsed document produces a log: sequence of (byte-distance, target-tag-hash)
  2. Logs stored in central ring buffer (10,000 entries)
  3. On new document, after first target: finds best-matching historical log
  4. Worker jumps directly to predicted target positions, skipping FSM for non-target regions
  5. Verifies predictions by peeking at tag hashes; falls back on mismatch

Accessing Logs

// Per-holder (after job completes)
long[] distances = holder.getLogDistances();
long[] hashes = holder.getLogHashes();
int size = holder.getLogSize();

// Global (all collected logs)
xmlBluePrint.LogEntry[] allLogs = xmlBluePrint.getCollectedLogs();
Works best for structurally similar XML (same tag order, variable spacing/attributes). No API changes needed — fully automatic.

9. Best Practices

Registration

  • Register only paths you need — smaller tree = faster matching
  • Use specific paths: /a/b/c not /a//c (no wildcards)
  • Reuse handlers with different tokens for same logic on different paths

Thread Count

  • Match to CPU cores for CPU-bound parsing
  • More threads help with I/O wait (large files from disk)
  • Avoid excessive threads (context switching overhead)

Memory

  • Reuse byte buffers when possible
  • Global queue: 16K jobs max; holder queue: 512 jobs each
  • Log store: 10K entries (fixed, ring buffer)

Error Handling

  • Always register error handler for production
  • Return false from callback to skip bad documents
  • Check EV_END_NE_BEGIN for malformed nesting
