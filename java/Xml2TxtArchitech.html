XML2TXT Architecture

3-phase design: BootUp → MainLoop → ClosingJob.

Components

  • XML2TXT main driver (CLI + pipeline control)
  • SourceHandler reads .xml / .zip from source folder
  • xmlBluePrint parser engine (predictive parsing, thread pool, pipeline slots)
  • EventHandlers / TokenRoot handle entities and columns via registered paths

Pipeline

Slot count = (2^N)-1: N=2 → 3, N=3 → 7, N=4 → 15, N=5 → 31.

Pipeline depth = -N (default 2, max 16). Slots = 2^N-1 (N2=3, N6=63, N8=255). Each +N ~doubles RAM (Factory/Stock). Sweet spot ≈ N6 for -t1; thread increase smaller gain than pipeline depth for IO-bound XML/zip.

Output

Per-entity PrintWriter writes to entityName_pending.txt; ClosingJob renames to timestamped .txt.
